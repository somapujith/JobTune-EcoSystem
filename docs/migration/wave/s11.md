## Code changes (shared files, the spike proved real defects)

| File | Change | Tests |
|---|---|---|
| `backend/src/worker/db.js` | (1) `query()`/`connect()` rejections that are not `Error` (the driver rejects with a bare `ErrorEvent` "Network connection lost" on a WebSocket connect failure) are wrapped in an `Error`, because Hono's `compose` only routes `instanceof Error` to `app.onError`; (2) `connect()` attaches an `'error'` listener to the checked-out client (pool listener does not cover it; was an uncaught exception); (3) errors arriving after `release()` began are dropped (workerd emits one for every socket the driver closes), non-Error events log at `warn`. | `tests/worker/db.test.js` +11 |
| `backend/src/config/database.worker.js` | `new Pool({ connectionString, max: 2, connectionTimeoutMillis: 10000 })`; exports `POOL_MAX`, `CONNECTION_TIMEOUT_MS`. Driver default `max 10` let one `dashboard.js` request (8 parallel queries) hold 8 connections, exhausting a 100-connection Postgres at 14 concurrent requests; now ~50. No connect timeout meant a black-holed endpoint hung the request; now 10 s then masked 500. | `tests/worker/databaseWorkerConfig.test.js` (new, 4) |
